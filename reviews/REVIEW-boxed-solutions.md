### Мелочи (факты)

- **М1.** Стр. 193: предупреждение фиксирует расхождение «2048 (Modelfile) vs 4k/32k/256k (Context length)», но FAQ даёт третье значение — «By default, Ollama uses 4096». Добавить его в предупреждение, вывод не меняется.
- **М2.** Стр. 74–77: «Linux — curl-пайп; macOS / Windows — установщик». По `ollama.com/download` curl-пайп официален и для macOS (`curl -fsSL https://ollama.com/install.sh | sh`), для Windows — `install.ps1`/exe. Подпись блока чуть уже реальности.
- **М3.** Стр. 432: «вендор заявляет +50% точности» (self-healing tool calling). У вендора осторожнее: «helps reduce broken or malformed tool calls by 50%» / «up to 50% more accurate». Заменить на «до +50% / −50% ошибок».
- **М4.** Стр. 392: «2× быстрее и на 70% меньше VRAM» — в README Unsloth scope явно про обучение (kernels), не про инференс. Добавить «(про обучение)» — иначе читатель перенесёт цифру на серв.
- **М5.** Стр. 463: «на Intel Mac локальный движок не поддерживается с v0.8.5». De jure неподдержка — с v0.8.0, в v0.8.5 лишь явно задокументирована (релиз v0.8.5, known issues v0.8.8). Уточнить формулировку.
- **М6.** Стр. 374–376 (`unsloth/gemma-4-26B-A4B-it-GGUF:UD-Q4_K_XL`) и 470–472 (`huggingface.co/mozilla-ai/llamafile_0.10/…/Qwen3.5-0.8B-Q8_0.llamafile`): существование этих точных тегов/путей не подтверждено (остальные примеры в главе — реальные). Copy-paste упадёт с «model not found». Пометить как иллюстративные или заменить проверенными.
- **М7.** Стр. 758: «деградация заметнее… на моделях с большим GQA». Двусмысленно: `q4_0` для KV больнее при *малом* числе KV-голов (агрессивном GQA). Переформулировать («при агрессивном GQA — малом числе KV-голов»), гл. 6 этого частного утверждения не содержит.
- **М8.** Стр. 497: «персональные API-ключи и учёт токенов» (LocalAI). Роли/OAuth/OIDC/ключи подтверждены доками Authentication; «учёт токенов» дословно не найден — смягчить или дать точную ссылку.
